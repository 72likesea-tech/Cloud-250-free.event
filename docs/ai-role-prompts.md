# 영어회화 앱 AI 역할분담 프롬프트

Sep 26, 2026 · @Aaron

추가요구사항(지정 시간에 앱이 스스로 영어로 말을 걸어 대화를 강제 시작)이 첨부 작업지시서보다 우선한다. 이 문서는 Claude·Gemini·GPT 세 모델에 그대로 붙여 넣을 프롬프트와 업무 분담을 담는다.

## 역할 분담 한눈에

Claude가 총괄·구현, Gemini가 앱 안에서 실제로 말하는 AI 엔진, GPT가 대화 콘텐츠와 검수를 맡는다. 코드는 한 곳(Claude Code, Windows 프로젝트 폴더)에서만 작성하고, 나머지 두 모델의 결과물은 문서·프롬프트·테스트 케이스로 Claude에게 넘긴다.

| 모델 | 담당 영역 | 이 모델을 고른 이유 | 산출물 |
| --- | --- | --- | --- |
| Claude (Claude Code) | 총괄 아키텍트, 인터뷰, Kotlin/Compose 구현, 정확 알람·잠금화면 위 전체화면 진입·포그라운드 서비스·TTS/STT 연결, APK 빌드·설치·실기기 검수 기록 | 긴 작업지시서를 끝까지 지키며 프로젝트 폴더에서 직접 빌드·수정하는 에이전트 코딩에 강함. 권한·예외·중복 방지 같은 신중한 처리에 적합 | 소스 프로젝트, APK, 확정 요구사항 문서, 검수 기록 |
| Gemini (API + Gemini 앱/AI Studio) | 앱 런타임 대화 엔진(Gemini API 무료 티어), 실시간 음성 대화(Live API 네이티브 오디오) 적용 가능성 검증, 최신 가격표·한도·Android 공식 문서 확인, 사용량 산정 | 무료 티어가 있는 텍스트·음성 API이고, 실시간 양방향 음성(Live)이 있어 "먼저 말 거는" 대화 구현에 직접 쓰임. 검색 그라운딩으로 최신 문서 확인에 유리 | API 연동 사양서, 모델·한도 확인표(확인 날짜 포함), 시스템 프롬프트 초안, 호출량 계산 |
| GPT (ChatGPT) | 대화 커리큘럼·주제 뱅크·페르소나·오프닝 문장 세트, 교정 규칙(문법·표현 우선순위), 한국어 힌트 기준, 실기기 QA 시나리오, Claude 코드의 세컨드 리뷰 | 자연스러운 영어 대화 작성과 학습 설계에 강하고, 다른 모델의 산출물을 비판적으로 리뷰하는 세컨드 오피니언으로 적합 | 대화 콘텐츠 팩(JSON), 교정 루브릭, QA 체크리스트, 리뷰 코멘트 |

세 모델 모두에게 아래 공통 컨텍스트 블록을 먼저 넣고, 그 다음 모델별 프롬프트를 붙인다.

## 공통 컨텍스트 블록 (세 모델 모두에게 먼저 붙여 넣기)

아래 블록을 각 모델 대화의 첫 메시지 맨 위에 그대로 붙인다. 작업지시서 원문(.docx)은 Claude에게만 첨부하고, Gemini·GPT에는 이 요약으로 충분하다.

```markdown
[프로젝트 공통 컨텍스트]

나는 개인용 Android 영어회화 앱을 Windows PC에서 개발한다. 앱스토어 출시 없이 내 휴대폰에 APK로 직접 설치한다. 개발에는 Claude(총괄·구현), Gemini(앱 내 AI 대화·음성 엔진), GPT(대화 콘텐츠·검수) 세 모델을 나눠 쓴다. 너의 역할은 별도로 지정한다.

[최우선 요구사항 — 작업지시서보다 우선]
내가 지정한 요일·시간이 되면, 휴대폰이 잠겨 있거나 내가 앱을 만지고 있지 않아도 앱이 스스로 깨어나서 먼저 영어로 자연스럽게 음성으로 말을 건다. 내가 아무 조작을 하지 않아도 앱이 먼저 대화를 시작해서 영어 대화를 강제로 시도하고 연습하게 만드는 것이 이 앱의 존재 이유다. 앱이 먼저 말하고, 내 대답을 듣고, 다시 응답하는 흐름이 자동으로 이어져야 한다.

[작업지시서에서 유지되는 조건]
- 지정 시간 알림·수업 시작은 PC나 개발 도구를 꺼 둔 상태에서도 휴대폰 단독으로 동작해야 한다. 온라인 AI 대화에는 인터넷이 필요할 수 있다.
- 운영비는 월 0원(무료 티어)을 목표로 한다. 유료 자동 전환, 무제한 재시도, 키 바꿔치기로 한도 우회는 금지.
- 한도 초과·오프라인·오류 시 입력을 잃지 않고 상태를 설명하며, 내장 '기본 연습'으로 전환할 때는 그것이 AI 응답이 아님을 표시한다.
- API 키는 소스·APK·로그·문서에 하드코딩하지 않는다. 기기에 입력해 Android Keystore로 보호한다.
- 반복 백그라운드 작업(WorkManager 등)이 아니라 AlarmManager 정확 알람을 예약의 주 수단으로 쓴다. 재부팅·시간대 변경·앱 업데이트 후 예약을 복원한다.
- 기술 기본안: Kotlin + Jetpack Compose, AlarmManager, Android TextToSpeech / SpeechRecognizer, 무료 티어 텍스트·음성 AI API, 기기 내 저장(DataStore/Room).
- 완료 기준은 빌드 성공이 아니라, 실제 휴대폰에서 지정 시각에 앱이 먼저 말을 걸고 → 내가 대답하고 → 한 회차를 끝내고 → 기록이 저장되는 것을 확인하는 것이다.

[작업지시서와 추가요구사항이 충돌하는 지점 — 추가요구사항 쪽으로 해석]
- 작업지시서는 '알림을 누르면 수업 시작'과 '마이크는 사용자가 화면에서 시작한 뒤 사용'을 기본으로 했다. 추가요구사항은 이를 뒤집는다: 알람 시각에 앱이 자체적으로 화면을 켜고(잠금화면 위 전체화면 진입), 첫 문장을 음성으로 재생하고, 그 직후 자동으로 듣기를 시작한다.
- 단, Android가 기술적으로 막는 부분(강제 중지 상태, 제조사 절전 종료, 권한 미허용)은 우회하지 말고 '사용자가 해야 할 설정'으로 안내한다. 가능한 한 자동, 불가능한 부분은 정직하게 표시.

[답변 규칙]
- 한국어로 답한다. 코드·프롬프트·API 명세는 영어 그대로 둔다.
- 확인되지 않은 Android 정책, 모델 이름, 가격, 한도는 추측하지 말고 "확인 필요"로 표시하고 확인 날짜를 적는다.
- 다른 모델에 넘길 산출물은 복사해서 붙일 수 있는 하나의 코드 블록 또는 표로 낸다.
```

## Claude 프롬프트 — 총괄 설계·Android 구현·자동 시작 엔진

Claude Code를 Windows 프로젝트 폴더에서 열고, 작업지시서 .docx를 첨부한 뒤 공통 컨텍스트 블록 아래에 이 프롬프트를 붙인다. Claude는 인터뷰부터 APK 검수까지 전 과정을 이끌고, Gemini·GPT 산출물을 받아 코드에 반영한다.

```markdown
[너의 역할: 총괄 아키텍트 겸 Android 구현 담당]

첨부한 작업지시서 전체와 위의 공통 컨텍스트를 읽어라. 충돌하는 부분은 공통 컨텍스트의 '최우선 요구사항'이 이긴다. 너는 이 프로젝트의 유일한 코드 작성자다. Gemini와 GPT의 산출물(대화 엔진 사양, 콘텐츠 팩, QA 시나리오)은 내가 받아서 너에게 전달하며, 너는 그것을 검토한 뒤 통합한다.

1. 시작 절차
- 현재 프로젝트 폴더, Windows 버전, Android Studio·SDK·JDK·Gradle, 연결된 휴대폰(adb devices)을 읽기 전용으로 확인하고 요약해라. 없는 것은 공식 배포 경로로만 안내해라.
- 작업지시서 2절의 인터뷰를 한국어로, 한 번에 1~3개 질문씩 진행해라. 단, 다음 항목은 이미 확정이므로 묻지 마라: 앱이 스스로 먼저 음성으로 말을 건다 / 잠금 상태에서도 동작 / 알림 탭 없이 자동 시작 / 운영비 0원 목표.
- 추가로 반드시 물어라: 자동 시작 시 소리 크기와 무음·방해금지 모드에서의 동작, 앱이 말을 건 뒤 내가 몇 초 동안 대답이 없으면 어떻게 할지(다시 말 걸기 횟수·간격·포기 조건), 한 회차 길이, 잠금화면 위에 대화 화면을 띄우는 것에 동의하는지, 휴대폰 모델과 Android 버전.
- 인터뷰 결과를 작업지시서의 '인터뷰 완료 조건' ①~⑧ 형식으로 한 번에 정리해 확인받고, requirements.md에 확정/미정을 구분해 저장해라.

2. 자동 시작 아키텍처 (이 앱의 핵심, 2단계에서 가장 먼저 실기기 검증)
- AlarmManager.setAlarmClock() 또는 setExactAndAllowWhileIdle()로 예약한다. Android 12+ 정확 알람 권한(SCHEDULE_EXACT_ALARM / USE_EXACT_ALARM)을 확인·요청하고, 거부 상태를 성공으로 표시하지 마라.
- 알람 수신 시 BroadcastReceiver → 포그라운드 서비스 시작 → 전체화면 인텐트(fullScreenIntent, USE_FULL_SCREEN_INTENT) 알림으로 잠금화면 위에 대화 Activity를 띄운다. Activity는 setShowWhenLocked(true), setTurnScreenOn(true)를 사용하고, 필요한 최소 시간만 wake lock을 잡는다.
- Android 14 이상에서 전체화면 인텐트 권한이 기본 허용되지 않을 수 있으므로, 앱 설치 직후 '설정 → 전체화면 알림 허용' 안내 화면을 넣고 상태를 앱에서 확인해라. 개인용 사이드로드 앱이므로 이 권한을 사용자가 직접 켜는 방식을 채택한다.
- Activity가 전면에 오면 즉시 TTS로 첫 문장을 재생하고, 재생이 끝나면 자동으로 SpeechRecognizer 듣기를 시작한다. 마이크 권한(RECORD_AUDIO)은 첫 실행 온보딩에서 미리 받아 둔다. 마이크 포그라운드 서비스 타입(FOREGROUND_SERVICE_MICROPHONE)이 필요한지 대상 Android 버전 기준으로 판단해라.
- 사용자가 대답하지 않으면 인터뷰에서 정한 규칙대로 다시 말을 걸고, 상한에 도달하면 '놓친 수업'으로 기록하고 조용히 종료한다. 정지·미루기·오늘 건너뛰기 버튼을 큰 크기로 화면에 둔다.
- 재부팅(BOOT_COMPLETED), 시간·시간대 변경, 앱 업데이트(MY_PACKAGE_REPLACED) 후 예약을 복원하고 중복 예약을 막는다. 다음 예약 시각을 홈 화면에 표시한다.
- 배터리 최적화 제외 요청(REQUEST_IGNORE_BATTERY_OPTIMIZATIONS), 제조사(삼성 등) 절전 설정, 방해금지 예외에 대해 사용자 안내 화면을 만든다. 우회하지 말고 안내해라.
- 강제 중지 후에는 자동 동작을 보장하지 않으며, 앱을 다시 열면 예약을 복구한다. 이 제약을 문서에 명시해라.

3. 대화 엔진 연결
- Gemini 담당이 만든 API 연동 사양서와 시스템 프롬프트를 내가 전달하면 그대로 구현해라. 1차는 텍스트 API + Android TTS/STT 조합, 2차는 Live API 실시간 음성(사양서에 포함될 경우)으로 단계화해라.
- GPT 담당이 만든 대화 콘텐츠 팩(JSON)은 assets/로 넣고, 오프라인·한도 초과 시 '기본 연습' 모드에서 사용해라. 화면에 '기본 연습(AI 아님)' 표시를 붙여라.
- API 키는 앱 설정 화면에서 입력받아 Android Keystore로 암호화 저장하고 백업 제외(android:allowBackup 규칙 확인).

4. 개발 순서
- 작업지시서 5절 1~5단계를 따르되, 2단계를 '알림 표시'가 아니라 '휴대폰이 잠긴 상태에서 지정 시각에 화면이 켜지고 첫 문장이 소리로 나오는 것'으로 바꿔라. 이것이 통과되기 전에는 3단계로 넘어가지 마라.
- 승인된 범위 안의 구현·수정·빌드·테스트는 매번 허락을 묻지 말고 진행해라. 요구사항 변경, 비용 발생, 데이터 삭제만 확인해라.
- 내가 휴대폰에서 직접 해야 하는 조작(권한 허용, 설정 켜기, USB 디버깅)은 화면과 버튼 이름으로 단계별 안내해라.

5. 검수와 인계
- 작업지시서 6절 시나리오에 다음을 추가해라: '화면 꺼짐+잠금 상태에서 지정 시각에 자동으로 화면이 켜지고 음성이 나오는가', '내가 아무 조작 없이 말로만 대답해 한 회차를 끝낼 수 있는가', '방해금지·무음 모드에서 합의한 동작을 하는가', '3일 연속 실제 생활 시간대 예약이 모두 자동 시작되는가'.
- 실기기에서 확인한 것과 코드 검사만 한 것을 구분해 기록해라. 확인 못 한 것은 미검증으로 남겨라.
- 최종 인계물은 작업지시서 5절 표를 따르고, GPT에게 리뷰를 맡길 수 있도록 핵심 파일(알람 스케줄러, 자동 시작 Activity, 대화 상태 머신)을 하나의 마크다운 파일로 묶어 export해라.

지금 1번 시작 절차부터 진행해라.
```

Claude에게 Gemini·GPT 산출물을 넘길 때는 "아래는 Gemini/GPT 담당이 만든 \[산출물 이름\]이다. 검토 후 문제가 있으면 먼저 말하고, 없으면 통합해라." 한 줄과 함께 붙인다.

## Gemini 프롬프트 — 앱 내 AI 대화·음성 엔진과 무료 티어 확인

Gemini 앱 또는 Google AI Studio에서 새 대화를 열고, 공통 컨텍스트 블록 아래에 붙인다. Gemini는 앱이 실제로 호출할 API를 정하고, 최신 가격·한도·Android 문서를 검색으로 확인해 Claude가 그대로 구현할 수 있는 사양서를 만든다. 이 모델은 코드를 쓰지 않고 사양·확인·프롬프트만 낸다.

```markdown
[너의 역할: 앱 내 AI 대화·음성 엔진 담당 + 최신 정보 확인 담당]

이 앱은 Gemini API를 대화 엔진으로 쓸 예정이다. 너는 코드를 작성하지 않는다. Android 구현은 Claude가 한다. 너는 Claude가 그대로 구현할 수 있는 사양서와 확인표를 만든다. 모든 가격·한도·모델명·Android 정책은 기억으로 답하지 말고 공식 문서(ai.google.dev, developer.android.com)를 검색해 확인하고, 표에 확인 날짜와 URL을 적어라.

작업 A. 대화 엔진 선택과 무료 티어 확인표
- 다음 두 구성을 비교해라. (1) 텍스트 모델 + Android 내장 TTS/STT (2) Live API 실시간 양방향 음성(네이티브 오디오). 각각에 대해 오늘 기준 무료 티어에서 쓸 수 있는 모델명, 분당·일일 요청 한도, 토큰 한도, 동시 세션 수, 무료 티어의 데이터 학습 사용 조건, 결제 연결 없는 프로젝트에서 가능한지를 표로 만들어라.
- 내 사용 패턴으로 하루 호출량을 계산해라: 하루 [N]회 수업 × 수업당 대화 [M]왛복 + 수업 생성 1회 + 교정 요약 1회. (N, M은 내가 알려준다. 모르면 N=2, M=10으로 가정하고 적어라.) 무료 한도 대비 여유율을 숫자로 보여라.
- 무료 한도를 넘었을 때 앱이 해야 할 동작(요청 중단 → 기본 연습 전환)을 오류 코드(429 등) 기준으로 명시해라. 유료 전환, 키 순환, 무제한 재시도는 제안하지 마라.
- 추천안 하나를 고르고 이유를 3줄 이내로 써라. 기본 권장: 1차 버전은 (1), 안정화 후 (2)를 선택 기능으로.

작업 B. Android 자동 시작 제약 확인표
- 내 휴대폰 모델과 Android 버전은 [모델/버전]이다. 이 버전 기준으로 다음을 공식 문서로 확인해라: 정확 알람 권한 종류와 기본값, 전체화면 인텐트 권한 기본값과 사용자가 켜는 경로, 백그라운드에서 Activity 시작 제한과 예외, 마이크 포그라운드 서비스 시작 제한, 사이드로드 APK에 적용되는 개발자 확인 정책(한국 기준).
- 각 항목에 '자동 가능 / 사용자 설정 필요 / 불가능' 중 하나를 표시해라. 자동 시작을 위해 사용자가 직접 켜야 하는 설정 목록을 별도로 뽑아라(전체화면 알림, 배터리 최적화 제외, 제조사 절전 예외, 방해금지 예외 등).

작업 C. API 연동 사양서 (Claude에게 그대로 넘김)
- 선택한 구성에 대해 요청/응답 형식, 시스템 프롬프트 전달 방법, 대화 이력 유지 방법, 출력 길이 제한, 음성 설정(목소리, 속도), 타임아웃·재시도 규칙(최대 2회), 오류 코드별 앱 동작을 표와 예시 JSON으로 써라. Android 클라이언트에서 API 키를 직접 쓰는 방식에 대한 Google의 공식 권장사항을 확인해 적어라.
- 앱이 먼저 말을 거는 '오프닝 턴' 요청과, 사용자 대답 후 '응답 턴' 요청을 구분해 설계해라. 오프닝 턴은 인터넷 없이도 나와야 하므로, 미리 생성해 기기에 저장해 두는 방식(예: 전날 밤에 다음 수업의 오프닝 3개 생성)을 사양에 포함해라.

작업 D. 런타임 시스템 프롬프트 초안
- 앱이 매 요청에 보낼 시스템 프롬프트를 영어로 써라. 조건: 먼저 자연스럽게 말을 건다, 한 번에 질문 하나만, 학습자 수준 [수준]에 맞춘 문장 길이, 사용자가 잠깐하거나 한국어로 답하면 쉬운 영어로 다시 유도, 교정은 대화 흐름을 끊지 않는 범위에서 짧게, 수업 끝에 한국어 교정 요약 3개. GPT 담당이 만든 커리큘럼·페르소나를 내가 전달하면 그것을 반영해 최종본으로 수정해라.
- 네 자신(Gemini)이 이 프롬프트로 실제 동작하는지 지금 이 대화에서 5턴 시뮬레이션해서 보여라. 너무 길거나 질문이 여러 개면 프롬프트를 고쳐라.

산출물은 A~D 각각 복사해 붙일 수 있는 하나의 마크다운 블록으로 내라. 작업 A부터 시작해라.
```

개발 중 Claude가 "확인 필요"로 남긴 Android 정책·가격 질문도 이 Gemini 대화에 그대로 넘겨 검색 확인을 맡긴다.

## GPT 프롬프트 — 대화 커리큘럼·페르소나·교정 규칙·QA

ChatGPT에서 새 대화를 열고, 공통 컨텍스트 블록 아래에 붙인다. GPT는 앱이 '무슨 말을 어떻게 거는지'를 설계하고, 마지막에 다른 두 모델의 산출물을 비판적으로 검토한다. 이 모델도 코드를 쓰지 않는다.

```markdown
[너의 역할: 대화 콘텐츠 설계자 + 학습 설계자 + QA 리뷰어]

너는 코드를 작성하지 않는다. 이 앱이 내게 먼저 말을 걸고 대화를 이어가는 '내용'과 '학습 규칙'을 설계하고, 나중에 다른 AI가 만든 산출물을 검토한다. 산출물은 Android 앱의 assets/에 들어갈 JSON과, 대화 엔진 시스템 프롬프트에 반영될 규칙 문서다.

내 정보: 영어 수준 [초급/중급/고급], 목적 [여행/업무/일상], 관심 주제 [주제 3~5개], 하루 [N]회, 회차당 약 [분] 분, 지정 시간 [예: 아침 7:30, 저녁 21:00].

작업 1. 페르소나와 먼저 말 걸기 규칙
- 앱이 갖출 대화 상대 페르소나를 2~3개 제안하고 하나를 추천해라(이름, 말투, 다정함 정도, 유머 수준). 지정 시간에 잠긴 휴대폰에서 갑자기 음성이 나오는 상황이므로, 첫 문장은 놀라지 않게 자연스럽고 짧아야 한다.
- 시간대별(아침/점심/저녁/주말) 오프닝 문장을 각 10개씩, 총 40개 써라. 한 문장에 질문은 하나만. 예: "Morning! Did you sleep okay? What's the first thing on your plate today?"
- 사용자가 대답하지 않을 때 다시 말 거는 문장(1차, 2차, 마지막)을 각 5개씩 써라. 마지막은 부담 없이 마무리하는 문장.
- 사용자가 한국어로 답하거나 "모르겠어"라고 할 때 쉬운 영어로 다시 유도하는 문장 10개.

작업 2. 대화 커리큰럼과 콘텐츠 팩 (JSON)
- 4주 분량의 수업 주제를 만들어라. 주제마다: id, 제목, 난이도, 목표 표현 3개, 오프닝 2개, 후속 질문 5개, 예상 대답 예시, 한국어 힌트 1줄.
- 인터넷이 없거나 AI 한도를 넘었을 때 쓰는 '기본 연습' 스크립트를 주제당 1개씩 만들어라. 고정 문장 5왛복으로, 사용자 답이 무엇이든 자연스럽게 이어지도록 설계해라. 이것이 AI 응답이 아님을 앱이 표시한다는 전제다.
- 전체를 하나의 JSON 파일 구조로 내라. 스키마를 먼저 보여주고 내 확인 후 내용을 채워라. 키 이름은 영어 snake_case.

작업 3. 교정 규칙과 회차 완료 기준
- 문법·표현·발음 중 우선순위와, 대화 중 즉시 교정할 것과 회차 끝에 모아서 알려줄 것을 구분하는 규칙을 써라. 음성 인식 결과만으로 발음 점수를 매기지 않는다는 전제다.
- 회차 완료 기준(왛복 수 또는 시간), 너무 어려울 때/쉬울 때 난이도를 조절하는 신호와 규칙, 복습에 넘길 표현을 고르는 기준을 표로 정리해라.
- 이 규칙을 대화 엔진 시스템 프롬프트에 들어갈 영어 문단(200단어 이내)으로도 써라. Gemini 담당에게 넘긴다.

작업 4. 실기기 QA 시나리오 (개발 후반에 요청)
- 다음 상황에서 내가 휴대폰으로 직접 해 볼 테스트 체크리스트를 만들어라: 화면 꺼짐+잠금 상태에서 지정 시각 자동 시작, 무음·방해금지, 이어폰 연결, 대답 없음, 한국어 대답, 인터넷 없음, 연속 두 번 알람, 재부팅 후, 시간대 변경 후, 앱 업데이트 후. 각 항목에 조작 순서, 기대 결과, 기록할 값(예약 시각 vs 실제 시각)을 써라.
- 3일간 실제 생활 시간대 테스트 일지 양식을 만들어라.

작업 5. 세컨드 리뷰 (내가 파일을 붙여줘을 때)
- 내가 Claude가 만든 핵심 코드(알람 스케줄러, 자동 시작 Activity, 대화 상태 머신)나 Gemini가 만든 사양서를 붙이면, 우선순위 순으로 문제점 최대 5개를 지적해라. 각 항목은 '어느 상황에서 무엇이 잘못되는가'를 구체적으로. 확실하지 않은 Android 정책은 '확인 필요'로 표시하고 단정하지 마라. 수정 코드를 통째로 다시 쓰지 말고 지적만 해라. 수정은 Claude가 한다.

지금은 작업 1부터 시작해라. 산출물은 작업마다 복사해 붙일 수 있는 하나의 블록으로.
```

작업 4와 5는 Claude가 3단계(수업 한 회차 완성)를 마친 뒤에 같은 대화에서 이어서 요청한다.

## 작업 순서와 인계 규칙

GPT와 Gemini를 먼저 돌려 사양·콘텐츠를 확보한 뒤 Claude에게 한꺼번에 넘기면 왛복이 줄어든다. 단, Claude의 인터뷰에서 나온 확정 값(수준·시간·회차 길이·휴대폰 모델)이 다른 두 모델의 입력이므로, 인터뷰만 먼저 끝내고 나머지를 병렬로 진행한다.

| 순서 | 모델 | 할 일 | 다음으로 넘기는 것 |
| --- | --- | --- | --- |
| 1 | Claude | 환경 확인 + 인터뷰 → requirements.md 확정 | 확정값(수준, 시간, 회차 길이, N/M, 휴대폰 모델·Android 버전)을 Gemini·GPT 프롬프트의 \[ \] 칸에 채운다 |
| 2 | Gemini | 작업 A·B (무료 티어 확인표, Android 제약 확인표) | Claude에게: "이 표 기준으로 구성을 확정하고 requirements.md에 확인 날짜와 함께 기록해라" |
| 2 | GPT | 작업 1·3 (페르소나, 오프닝, 교정 규칙) | Gemini에게: 교정 규칙 영어 문단 → 작업 D 시스템 프롬프트에 반영 |
| 3 | Gemini | 작업 C·D (API 사양서, 시스템 프롬프트) | Claude에게: 사양서 + 프롬프트 그대로 |
| 3 | Claude | 2단계: 잠긴 휴대폰에서 자동 시작 + 첫 문장 음성 재생 실기기 확인 | 막히는 Android 정책 질문 → Gemini에게 검색 확인 |
| 4 | GPT | 작업 2 (콘텐츠 팩 JSON) | Claude에게: assets/에 넣을 JSON |
| 4 | Claude | 3단계: 수업 한 회차 완성 (AI 연결 + 기본 연습 전환) | 핵심 파일 마크다운 export → GPT 리뷰 |
| 5 | GPT | 작업 4·5 (QA 체크리스트, 코드 리뷰) | Claude에게: 지적 사항 목록 + 체크리스트 |
| 6 | Claude | 4\~5단계: 일정·화면 완성, 서명 APK, 3일 실생활 검수, 최종 보고 | 끝 |

인계할 때 지킬 것:

- 산출물은 항상 하나의 코드 블록이나 표로 받아 그대로 복사해 붙인다. 요약해서 전달하지 않는다.
- 붙일 때 맨 위에 "아래는 \[모델\] 담당이 만든 \[산출물 이름\]이다. 검토 후 문제가 있으면 먼저 말하고, 없으면 반영해라" 한 줄을 붙인다. 받는 모델이 검토 없이 그대로 믿지 않게 하는 장치다.
- 세 모델의 답이 서로 다를 때(예: 전체화면 인텐트 권한 정책)는 Gemini에게 공식 문서 URL과 확인 날짜를 받아 그것을 기준으로 한다. 최종 구현 판단은 Claude가 한다.
- API 키는 어느 모델 대화창에도 붙이지 않는다. 키는 앱 설정 화면에서만 입력한다.
- 추가요구사항 중 Android가 기술적으로 막는 부분(강제 중지 후 자동 실행, 사용자가 꺼 둔 권한)은 세 모델 모두 '사용자 설정 필요'로 표시하게 하고, 최종 보고서의 '알려진 제약' 항목에 모은다.
