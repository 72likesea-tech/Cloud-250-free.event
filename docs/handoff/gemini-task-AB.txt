[프로젝트 공통 컨텍스트]

나는 개인용 Android 영어회화 앱을 개발한다(Claude Code 클라우드 환경에서 빌드). 앱스토어 출시 없이 내 휴대폰에 APK로 직접 설치한다. 개발에는 Claude(총괄·구현), Gemini(앱 내 AI 대화·음성 엔진), GPT(대화 콘텐츠·검수) 세 모델을 나눠 쓴다. 너의 역할은 별도로 지정한다.

[최우선 요구사항 — 작업지시서보다 우선]
내가 지정한 요일·시간이 되면, 휴대폰이 잠겨 있거나 내가 앱을 만지고 있지 않아도 앱이 스스로 깨어나서 먼저 영어로 자연스럽게 음성으로 말을 건다. 내가 아무 조작을 하지 않아도 앱이 먼저 대화를 시작해서 영어 대화를 강제로 시도하고 연습하게 만드는 것이 이 앱의 존재 이유다. 앱이 먼저 말하고, 내 대답을 듣고, 다시 응답하는 흐름이 자동으로 이어져야 한다.

[작업지시서에서 유지되는 조건]
- 지정 시간 알림·수업 시작은 PC나 개발 도구를 꺼 둔 상태에서도 휴대폰 단독으로 동작해야 한다. 온라인 AI 대화에는 인터넷이 필요할 수 있다.
- 운영비는 월 0원(무료 티어)을 목표로 한다. 유료 자동 전환, 무제한 재시도, 키 바꿔치기로 한도 우회는 금지.
- 한도 초과·오프라인·오류 시 입력을 잃지 않고 상태를 설명하며, 내장 '기본 연습'으로 전환할 때는 그것이 AI 응답이 아님을 표시한다.
- API 키는 소스·APK·로그·문서에 하드코딩하지 않는다. 기기에 입력해 Android Keystore로 보호한다.
- 반복 백그라운드 작업(WorkManager 등)이 아니라 AlarmManager 정확 알람을 예약의 주 수단으로 쓴다. 재부팅·시간대 변경·앱 업데이트 후 예약을 복원한다.
- 기술 기본안: Kotlin + Jetpack Compose, AlarmManager, Android TextToSpeech / SpeechRecognizer, 무료 티어 텍스트·음성 AI API, 기기 내 저장(DataStore/Room).
- 완료 기준은 빌드 성공이 아니라, 실제 휴대폰에서 지정 시각에 앱이 먼저 말을 걸고 → 내가 대답하고 → 한 회차를 끝내고 → 기록이 저장되는 것을 확인하는 것이다.

[작업지시서와 추가요구사항이 충돌하는 지점 — 추가요구사항 쪽으로 해석]
- 작업지시서는 '알림을 누르면 수업 시작'과 '마이크는 사용자가 화면에서 시작한 뒤 사용'을 기본으로 했다. 추가요구사항은 이를 뒤집는다: 알람 시각에 앱이 자체적으로 화면을 켜고(잠금화면 위 전체화면 진입), 첫 문장을 음성으로 재생하고, 그 직후 자동으로 듣기를 시작한다.
- 단, Android가 기술적으로 막는 부분(강제 중지 상태, 제조사 절전 종료, 권한 미허용)은 우회하지 말고 '사용자가 해야 할 설정'으로 안내한다. 가능한 한 자동, 불가능한 부분은 정직하게 표시.

[답변 규칙]
- 한국어로 답한다. 코드·프롬프트·API 명세는 영어 그대로 둔다.
- 확인되지 않은 Android 정책, 모델 이름, 가격, 한도는 추측하지 말고 "확인 필요"로 표시하고 확인 날짜를 적는다.
- 다른 모델에 넘길 산출물은 복사해서 붙일 수 있는 하나의 코드 블록 또는 표로 낸다.

[인터뷰로 확정된 값 — 2026-09-26]
- 기기: Galaxy S24 Ultra, One UI 8.5, Android 16. 사용 국가 한국. 사이드로드 APK로 설치.
- 학습자: 영어 초급 상 ~ 중급 하. 목적은 여행·업무·일상·비즈니스·토론 전 영역. 한국어는 막힐 때 말문을 여는 용도로만.
- 일정: 매일 14:00에 첫 말걸기. 하루 1회(N=1), 한 회차 5~10분, 약 10왕복(M=10).
- 재시도: 패스·대답 없음·무음 모드·방해금지 무반응이면 1시간 뒤 재시도, 20:00까지. 그날 회차를 끝내면 다음 날 14:00.
- 대답 없음: 8초 기다린 뒤 1회만 다시 말걸기 → 그래도 없으면 종료.
- 무음(매너) 모드: 말을 걸지 않음. 방해금지: 소리 없이 화면+진동, 터치하면 시작(30초 무반응이면 종료).
- 대화 시작: 첫 인사 → 오늘 주제를 영어로 묻는다. 선택지는 "work(비즈니스·업무)", "travel(여행·일상)", 그리고 그날의 구체적인 토론 질문 하나(예: "Should companies adopt a four-day work week?"). '의견과 토론'이라는 이름으로 묻지 않고 토론 질문 자체를 바로 제시한다.
- 교정: 대화 중에는 흐름을 끊지 않고 자연스러운 표현으로 한 번 되받아 말하기(recast). 회차가 끝나면 한국어 교정 요약 3개.
- AI: 사용자가 이미 만든 Gemini API 키(결제 미연결, 월 0원 필수). 대화 응답과 종료 후 요약 모두 gemini-2.5-flash-lite 예정(확인 필요).
- 외부 전송: 음성을 글자로 바꾼 대화 텍스트만 Gemini로 보냄. 음성 원본은 저장하지 않음.
- 2단계(잠긴 휴대폰에서 14:00에 화면이 켜지고 첫 문장이 소리로 나옴)는 구현 완료, 실기기 검수 중.

[너의 역할: 앱 내 AI 대화·음성 엔진 담당 + 최신 정보 확인 담당]

이 앱은 Gemini API를 대화 엔진으로 쓸 예정이다. 너는 코드를 작성하지 않는다. Android 구현은 Claude가 한다. 너는 Claude가 그대로 구현할 수 있는 사양서와 확인표를 만든다. 모든 가격·한도·모델명·Android 정책은 기억으로 답하지 말고 공식 문서(ai.google.dev, developer.android.com, 필요 시 samsung.com)를 검색해 확인하고, 표에 확인 날짜와 URL을 적어라.

이번에는 작업 A와 작업 B만 해라. 작업 C·D(API 연동 사양서, 런타임 시스템 프롬프트)는 나중에 따로 요청한다.

작업 A. 대화 엔진 선택과 무료 티어 확인표
- 다음 두 구성을 비교해라. (1) 텍스트 모델 + Android 내장 TTS/STT (2) Live API 실시간 양방향 음성(네이티브 오디오). 각각에 대해 오늘 기준 무료 티어에서 쓸 수 있는 모델명, 분당·일일 요청 한도(RPM/RPD), 분당 토큰 한도(TPM), 동시 세션 수, 무료 티어의 데이터 학습 사용 조건, 결제 연결 없는 프로젝트에서 가능한지를 표로 만들어라.
- 특히 gemini-2.5-flash-lite가 오늘 기준 무료 티어에서 제공 중인지, 지원 종료(deprecation/shutdown) 예정일이 있는지, 후속 권장 모델이 무엇인지 확인해라.
- 내 사용 패턴으로 하루 호출량을 계산해라: 하루 1회 수업 × 수업당 대화 10왕복 + 수업 생성 1회 + 교정 요약 1회. 재시도 회차는 대화가 성립하지 않으면 호출 0회다. 대화 문맥(이전 턴 포함) 기준 1회 요청당 대략 토큰 수도 추정해라. 무료 한도 대비 여유율을 숫자로 보여라.
- 무료 한도를 넘었을 때 앱이 해야 할 동작(요청 중단 → 기본 연습 전환)을 오류 코드(429 등) 기준으로 명시해라. 유료 전환, 키 순환, 무제한 재시도는 제안하지 마라.
- 추천안 하나를 고르고 이유를 3줄 이내로 써라. 기본 권장: 1차 버전은 (1), 안정화 후 (2)를 선택 기능으로.

작업 B. Android 자동 시작 제약 확인표
- 내 휴대폰은 Galaxy S24 Ultra, One UI 8.5, Android 16이다. 이 버전 기준으로 다음을 공식 문서로 확인해라.
  1) 정확 알람 권한 종류(USE_EXACT_ALARM / SCHEDULE_EXACT_ALARM)와 기본값. 사이드로드 앱이 USE_EXACT_ALARM을 선언하면 설치 즉시 허용되는지.
  2) 전체화면 인텐트(USE_FULL_SCREEN_INTENT) 권한의 기본값과 사용자가 켜는 설정 경로(One UI 메뉴 이름으로).
  3) 백그라운드에서 Activity 시작 제한과 예외(전체화면 인텐트 알림이 잠금·화면 꺼짐 상태에서 Activity를 띄우는지, 화면이 켜져 있고 잠금 해제 상태면 어떻게 되는지).
  4) 잠금화면 위 Activity(setShowWhenLocked/setTurnScreenOn)에서 마이크(SpeechRecognizer) 사용 가능 여부와 제한.
  5) 방해금지 모드에서 전체화면 인텐트와 CATEGORY_ALARM 알림이 어떻게 처리되는지(One UI의 방해금지 예외 설정 포함).
  6) 사이드로드 APK에 적용되는 Google 개발자 확인(developer verification) 정책의 한국 적용 시기와 개인 사용 앱에 미치는 영향.
  7) 삼성 One UI 절전 기능(절전 예외 앱, 사용하지 않는 앱 절전 등)이 정확 알람에 주는 영향과 사용자 설정 경로.
- 각 항목에 '자동 가능 / 사용자 설정 필요 / 불가능' 중 하나를 표시해라. 자동 시작을 위해 사용자가 직접 켜야 하는 설정 목록을 별도로 뽑아라(전체화면 알림, 배터리 최적화 제외, 제조사 절전 예외, 방해금지 예외 등).

산출물은 작업 A, 작업 B 각각 복사해 붙일 수 있는 하나의 마크다운 블록으로 내라. 작업 A부터 시작해라.
